# Kiltikonet rebuild baseline — CVLN iOS aligned

Status: WORKING BASELINE  
Branch: `rebuild/kiltikonet-institution-2026-09`  
Source basis: route/interface atlas derived from the current repository, then cross-checked against `cultureconnectorg/Cvln-ios-v.1` v1.1-patch.1.

## Governing reconstruction rule

Kiltikonet is rebuilt as a **Layer-4 cultural/business system**. It may expose product surfaces, operational tools and cultural observatories, but it must not silently become a second CVLN operating system.

CVLN iOS boundaries to preserve:

- META CVLN: constitution, estate governance, registry, permissions, runtime state.
- CVL BRAIN: doctrine, cognition, reasoning and model-routing target owner.
- CVLN Agent Factory: agent runtime, lifecycle, gates, scheduler, execution.
- Laurentia: cultural-industry operator and orchestration surface.
- FREKCORE / FREK-ID: identity and proof services consumed by Kiltikonet.
- Kiltikonet: cultural/institutional product system and programme host.

## Product hierarchy

### 1. Kiltikonet.fr — institutional/public core

### 2. Culture Connect — programme/event universe

Culture Connect is a programme/product carried by Kiltikonet, not the definition of Kiltikonet itself.

Existing surfaces to preserve and progressively namespace:

- `/culture-connect`
- `/culture-connect/2026`
- `/culture-connect/2027` (future edition, not treated as verified runtime capability)
- programme
- concert

- confirmations
- badge/accreditation/scanner/participant operations

Legacy direct routes remain compatibility aliases until the migration is complete.

### 3. Kiltikonet Network — TARGET, not current-state claim

CVLN iOS audit marks the following as not evidenced in the audited Kiltikonet repository:

- territorial operator network
- hubs
- licences/franchises
- deployment standards
- network governance
- quality control
- operator certification/training
- international footprint
- upward reporting / network KPIs

Therefore the rebuild may prepare the product boundary, contracts and UX, but must label the Network as a target/in-structuring capability until implementation evidence exists.

### 4. Kiltikonet Academy — TARGET

The Academy name appears in target material, but no Kiltikonet Academy artefact was verified in the audited Kiltikonet repository. The preferred architecture is a Kiltikonet-branded training vertical powered by the shared CVLN Academy learning engine rather than a duplicate LMS.

No UI should claim Academy is implemented until the integration is real and tested.

### 5. Observatory — cultural domain, not estate observability

`/observatory` is retained as the cultural/data observatory of Kiltikonet.

It must remain distinct from CVLN estate observability/runtime-state responsibilities owned by META in the target architecture.

### 6. Espace Pro / workspaces / admin

These are valid application surfaces, but they are not CVLN OS ownership surfaces.

- Espace Pro stays a product/application UI.
- Workspaces stay operational UIs.
- Admin dashboards stay business/back-office UIs.
- Cross-estate permissions, registry, gates, doctrine and agent lifecycle must not be reimplemented locally.

### 7. Smart Engine / AI Agents

High-priority boundary fix.

Current Kiltikonet exposes Smart Engine and AI Agent monitoring while also using direct provider access. CVLN iOS target architecture assigns:

- cognition/model routing -> CVL BRAIN
- agent runtime/lifecycle/gates -> CVLN Agent Factory

Target state for Kiltikonet:

- dashboards become consoles/consumers of shared CVLN services;
- no Kiltikonet-owned doctrine;
- no independent model-routing authority;
- no independent agent lifecycle authority.

Until those integrations exist, these surfaces should be protected/internal and clearly treated as operational tooling rather than sovereign intelligence ownership.

## Evidence discipline

Every future rebuild change must be classified as one of:

- OBSERVED — present in current Kiltikonet code/data;
- IMPLEMENTED — executable code exists;
- VERIFIED — tested runtime evidence exists;
- TARGET — desired future architecture;
- OPEN — unresolved decision/contradiction;
- LEGACY — retained for compatibility/history.

Do not convert TARGET or OPEN items into EXISTING claims through UI copy alone.
